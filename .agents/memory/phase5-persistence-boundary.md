---
name: Phase 5 persistence boundary
description: Operational boundary for task orchestration and generated artifacts after Phase 5.
---

Phase 5 task groups and artifact metadata are currently held by process-local
stores, while generated bytes are written to a local temporary artifact
directory. This is suitable for the bounded foundation and tests, not for
durable production history or cross-restart recovery.

**Why:** The phase explicitly focused on finite orchestration, skill execution,
and tenant/user access contracts without introducing a new persistence schema
or changing the existing database boundary.

**How to apply:** Before production task history, resumability, or artifact
retention is promised, add tenant-scoped durable task/artifact records,
ownership checks, expiry cleanup, and restart/recovery tests. Do not silently
replace the current local store with a different database.
