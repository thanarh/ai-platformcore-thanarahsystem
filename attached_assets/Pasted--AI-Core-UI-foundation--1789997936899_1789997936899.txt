# PHASE 3.1 — WEB SOURCE EXPANSION

## الهدف

نقل Web Intelligence من:

```text
SearXNG
└── Wikipedia only
```

إلى Web Search حقيقي متعدد المصادر من خلال SearXNG.

ممنوع إضافة:

* Google paid API
* SerpAPI
* Tavily
* Bing paid API
* OpenAI
* Anthropic
* Gemini
* Groq
* OpenRouter
* أي AI/search provider مدفوع

SearXNG يظل طبقة البحث الوحيدة.

---

## 1. SearXNG Engines

افحص الـ SearXNG الحالي واكتشف الـ engines المتاحة فعليًا.

لا تفترض أنها موجودة.

اعرض capability واضحة:

```text
GET /web/capabilities
```

مثل:

```json
{
  "enabled": true,
  "engines": [],
  "categories": [],
  "healthy": true
}
```

استخدم فقط engines التي تعمل فعليًا في البيئة.

لا تسجل engine على أنه متاح لمجرد وجوده في configuration.

---

## 2. Search Categories

جهز architecture تدعم:

```text
general
news
technical
documentation
```

بحيث السؤال يختار نوع البحث المناسب.

مثال:

```text
"آخر أخبار الذكاء الاصطناعي"
→ news

"كيف أستخدم React Server Actions؟"
→ technical/documentation

"ما سعر X الحالي؟"
→ general/current

"ابحث لي عن..."
→ general
```

لا تجعل Qwen مسؤولًا وحده عن تحديد category.

استخدم deterministic signals + model assistance عند الحاجة.

---

## 3. Google-like Search

المستخدم عندما يقول:

```text
ابحث في جوجل عن...
```

لا نحتاج Google API مباشرة.

حوّل الطلب إلى:

```text
Web Search
→ SearXNG
```

مع إرجاع نتائج متعددة المصادر.

لا تقول للمستخدم إنه تم استخدام Google إذا لم يكن Google هو المصدر الفعلي.

---

## 4. Search Quality

لا ترسل كل النتائج إلى Qwen.

Pipeline:

```text
SearXNG
 ↓
Deduplicate
 ↓
Domain filtering
 ↓
Lexical relevance
 ↓
Local reranking
 ↓
Top sources
 ↓
Fetch
 ↓
Extract
 ↓
Context compression
 ↓
Qwen
```

---

## 5. Source Diversity

حاول الحصول على أكثر من domain عندما يكون ذلك مناسبًا.

مثال:

```text
source 1 → official
source 2 → documentation
source 3 → reputable secondary source
```

ولا تكرر نفس الموقع 5 مرات إذا توجد مصادر مستقلة أفضل.

---

## 6. Citations

استمر في النظام الحالي:

```text
[source-1]
[source-2]
[source-3]
```

ويجب أن يكون كل source حقيقيًا من retrieval pipeline.

الموديل ممنوع اختراع:

* URL
* domain
* title
* source

---

## 7. Security

احتفظ بكل SSRF protections الموجودة.

لا تضعف أي protection لإضافة engines جديدة.

Web content يظل:

```text
UNTRUSTED DATA
```

ولا يستطيع تغيير system prompt أو permissions أو tools.

---

## 8. Benchmark

استخدم 20 query حقيقية:

```text
5 general
5 technical
5 news/current
5 explicit search requests
```

وقس:

```text
search latency
fetch latency
extraction latency
reranking latency
total latency
successful fetch rate
source diversity
citation integrity
```

قارن النتائج بالـ Phase 3 benchmark.

لا تستخدم fixture numbers بدل live numbers.

---

## 9. Production

لا تفعّل production تلقائيًا.

احتفظ:

```text
WEB_SEARCH_ENABLED=false
```

حتى تنجح الـ live tests.
