Phase 5.1 تم اعتمادها بنجاح.

نبدأ الآن:

# PHASE 6 — LOCAL VOICE INTELLIGENCE

الهدف هو إضافة Voice حقيقي إلى Thanarah Intelligence، مع استخدام نفس AI Core الحالي.

لا نبني chatbot صوتي منفصل.

الصوت مجرد channel فوق الـexisting conversation/AI gateway/orchestrator.

---

# 1. Architecture

نفذ:

```text id="wq2p5d"
Microphone
    ↓
Voice Input
    ↓
Speech-to-Text
    ↓
Existing Conversation
    ↓
AI Gateway
    ↓
Skills / Tools / Tasks
    ↓
Text Response
    ↓
Text-to-Speech
    ↓
Audio Response
```

Voice يجب أن يستخدم نفس:

* authentication
* tenant isolation
* user context
* conversation
* permissions
* skills
* tools
* task orchestrator
* artifacts

لا تنشئ AI logic ثانية للصوت.

---

# 2. Local Only

ممنوع:

* OpenAI Whisper API
* Google Speech API
* Azure Speech
* AWS Transcribe
* ElevenLabs
* Google TTS
* أي paid speech API
* أي external AI provider

نريد:

```text id="q5l6m1"
LOCAL STT
+
LOCAL TTS
```

إذا كانت مكتبة/موديل غير موجود، افحص أولًا ما هو متاح حاليًا في البيئة.

لا تحمل موديلات ضخمة عشوائيًا.

---

# 3. STT Model Discovery

افحص البيئة الحالية أولًا.

```text id="3b4gqp"

24GB RAM

```

ولا تغير production قبل benchmark.

إذا كان هناك أكثر من خيار صغير مناسب، اختبر عددًا محدودًا فقط.

لا تنزل عدة موديلات كبيرة.

**Push-to-talk هو الأساس.**

```text id="kjl12m"
voice streaming
```

لا تجعل frontend يتصل مباشرة بالموديل.

---

# 7. Conversation Integration

عندما يرسل المستخدم صوتًا:

```text id="j8x5x3"
Audio
 ↓
STT
 ↓
Transcript
 ↓
Existing chat pipeline
```

والـtranscript يظهر كرسالة مستخدم عادية.

مثال:

```text id="7g9p2v"
🎙 "احسب لي مواعيد بكرة"
```

ثم نفس الـAI pipeline.

---

# 8. Response

الـAI response يجب أن يكون:

```text id="k2w8j1"
Text
+
Optional Audio
```

لا تجعل Voice response منفصلة عن text response.

إذا TTS فشل:

```text id="7wz3sl"
Text response still succeeds
```

ولا يفشل الـchat بالكامل.

---

# 9. Streaming

أريد architecture تسمح:

```text id="z6k8l3"
STT
 ↓
AI response streaming
 ↓
TTS chunks
 ↓
Audio playback
```

لكن لا تدخل في full duplex/interruptions المعقدة الآن إذا كانت ستزيد complexity بشكل كبير.

Push-to-talk أولًا.

# 10. Arabic

يجب اختبار:

### Arabic

```text id="k2g7u8"
"السلام عليكم، عندي موعد بكرة الساعة خمسة."
```

### Arabic + English

```text id="x1a2m9"
"أريد أعمل PDF report عن المواعيد."
```

### English

```text id="v8b3n4"
"Summarize this document for me."
```

لا يكفي أن STT يعيد نصًا غير فارغ.

نحتاج تسجيل:

```text id="n4p5r6"
transcription latency
transcription result
language detection
```

ولا تسجل raw audio في logs.

---

# 11. Audio Privacy

لا تحفظ raw audio دائمًا.

الـdefault:

```text id="9f8e7d"
process
→ transcribe
→ discard audio
```

إذا احتجنا persistence لاحقًا ستكون feature منفصلة.

لا تضع recordings في MongoDB.

---

# 12. Voice Security

اختبر:

* unauthenticated voice request
* cross-tenant conversation
* oversized audio
* invalid MIME type
* malformed audio
* duration limit
* request timeout
* concurrent voice requests

ضع limits واضحة على:

```text id="1a3b5c"
file size
duration
concurrency
```

# 14. Interruption

Phase 6 الأولى لا تحتاج full duplex.

لكن يجب أن يكون هناك:

```text id="7d3f2a"
Stop audio
```

إذا المستخدم ضغط stop:

```text
audio playback stops
```

ولا يفسد conversation state.

# 15. Voice + Skills

اختبر أن Voice لا يعمل كنظام منفصل.

مثلاً:

```text id="h7j4k2"

"حلل الملف ده"
```

يجب أن يصل إلى:

```text id="m6n8p1"

→ STT
→ file_analysis skill
→ task
→ result
```

مثال آخر:

```text id="r4t6y8"
User voice:
"نظم لي المهام دي"
```

يذهب إلى:

```text id="s2d5f7"
task_organization
```
