# PHASE 7 — THANARAH CORE INTEGRATION AUDIT

هذه المرحلة ليست تنفيذ integration وهمي.

الهدف هو اكتشاف وبناء **العقد الحقيقي** الذي سيستخدمه AI Core للتعامل مع Thanarah Core.

لدينا حاليًا:

```text
AI Gateway ✓
Tool Registry ✓
Permissions ✓
Tenant Isolation ✓
Task Orchestrator ✓
Skills ✓
Artifacts ✓
Voice ✓
```

لكن:

```text
THANARAH_CORE_TOOLS_ENABLED=false
```

لأنه لا يوجد contract موثق ومصادق عليه لـ Thanarah Core حتى الآن.

---

# 1. IMPORTANT

لا تخترع:

* API endpoints
* database collections
* authentication scheme
* tenant identifiers
* field names
* appointment schemas
* doctor schemas
* service schemas

إذا لم تكن موجودة فعليًا في Thanarah Core، لا تنشئها من التخمين.

---

# 2. Audit Thanarah Core

افحص فقط ما هو موجود فعليًا في المشروع/البيئة المتاحة.

ابحث عن:

```text
API routes
controllers
services
schemas
DTOs
database models
authentication
authorization
tenant model
organization model
user model
appointment model
doctor model
service model
working-hours model
insurance model
clinic model
```

وحدد العلاقة بينها.

# 3. Existing API Contract

إذا وجدت APIs حقيقية، وثق لكل endpoint:

# 4. AI Tool Mapping


إذا لم يوجد endpoint مناسب:

```text

```

ولا تعمل mock replacement.

# 6. Authentication

حدد طريقة authentication الحقيقية بين:

```text id="m5v8c2"

        ↓
Thanarah Core
```

هل هي:

```text
service token?
JWT?
internal API key?
OAuth?
session?
```

لا تخترع واحدة.

إذا لا يوجد service-to-service authentication حاليًا:

```text
NOT IMPLEMENTED
```

وثق المطلوب فقط.

ولا تنشئ secrets عشوائية.
